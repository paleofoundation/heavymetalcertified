<section id="v1" class="hmtc-section">
  <h2 style="font-family:Lora,serif;font-weight:400;font-size:30px;line-height:1.2;color:#2b1f1f;border-bottom:1px solid #e8e1db;padding-bottom:10px">What Method v1 was</h2>
  <p style="font-size:16.5px;line-height:1.78;color:#3f3a3a;margin:0 0 18px;max-width:var(--prose-max)">Method v1 was rigorous in intent. It tried to set every subcategory and analyte cell from Heavy Metal Index occurrence literature: pool the findings for that product form, pick a percentile, publish a number. The government-limit lookup that Method v2 uses as the default did not govern those cells.</p>
  <p style="font-size:16.5px;line-height:1.78;color:#3f3a3a;margin:0 0 18px;max-width:var(--prose-max)">v1 also carried a two-class analyte status ladder and an overage metric, MaxPoL, with status bands above the published limit. A product could sit over a published number and still hold a transitional status. That architecture is retired. It is named here so a reader can see what was killed, not so it can be used.</p>
</section>

<section id="why" class="hmtc-section">
  <h2 style="font-family:Lora,serif;font-weight:400;font-size:30px;line-height:1.2;color:#2b1f1f;border-bottom:1px solid #e8e1db;padding-bottom:10px">Why it was unacceptable</h2>
  <p style="font-size:16.5px;line-height:1.78;color:#3f3a3a;margin:0 0 18px;max-width:var(--prose-max)">The occurrence pool was too thin. Many subcategory and analyte cells had missing or single-survey data. The generator still had to emit a number. Calculation mistakes, thin pools, and confidence scores that could not carry a live certification decision produced limits that moved when the corpus or the code moved.</p>
  <p style="font-size:16.5px;line-height:1.78;color:#3f3a3a;margin:0 0 18px;max-width:var(--prose-max)">That volatility is unacceptable for published limits and for a mark a retailer or a regulator will treat as a fact. A certification program needs numbers a hostile reader can re-derive from a named instrument, not from a pool that changes under them.</p>
  <p style="font-size:16.5px;line-height:1.78;color:#3f3a3a;margin:0 0 18px;max-width:var(--prose-max)">Reproducibility failed the legal-defensibility test in the Governing Principles. Every published number has to trace to a named sovereign maximum or a disclosed read-across. Incomplete claim-surface cells are not cert-ready. Speed suffered for the same reason: the program could not ship a cell it could not defend.</p>
</section>

<section id="v2" class="hmtc-section">
  <h2 style="font-family:Lora,serif;font-weight:400;font-size:30px;line-height:1.2;color:#2b1f1f;border-bottom:1px solid #e8e1db;padding-bottom:10px">What Method v2 changed</h2>
  <p style="font-size:13.5px;line-height:1.7;color:#736b6b;margin:0 0 20px;max-width:84ch">Method v2.0 was ratified on 2026-08-03 as a government-limit default. Later locks on the same edition gutted the remaining brittle pieces: claim cells, status, and mint gates.</p>
  <div style="overflow-x:auto">
  <table>

        <td>Limits</td>
        <td>Occurrence pool of Index findings for every subcategory and analyte</td>

      </tr>

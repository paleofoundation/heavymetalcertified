# HeavyMetalCertified.com brand-cohesion audit

Audit date: 2026-08-12

## Outcome

The public Heavy Metal Tested & Certified site now presents one coherent, product-specific certification system centered on readiness, confidentiality boundaries, predictable consequences, evidence reuse, remediation, proof, and ongoing control. The implementation removes invented products and promises while making future operational capabilities explicit and safely gated.

This work belongs to `paleofoundation/heavymetalcertified`, the repository linked to the `heavymetalcertified` Vercel project and the `heavymetalcertified.com` production domain. It does not place certification authority, client data, or commercial workflow inside `paleofoundation/heavymetalindex`. The Index remains the separate public evidence layer.

## Audit scope and evidence

- 155 public Markdown source pages were inspected by the direction and design lints.
- 158 emitted HTML routes were rendered at desktop and mobile widths.
- 17,599 local links and asset references were resolved against the built site.
- The six-question readiness interaction was completed and reset in a real browser; it emitted no request and stored no applicant record.
- 87 computed-style and content acceptance assertions passed against the rendered build.
- TypeScript, generators, firewall and content lints, production build, route crawl, browser checks, and crawl-metadata audit passed.

These counts describe the audited build and are verification evidence, not public marketing claims.

## Direction implemented

| Direction | Implemented public behavior | Operational boundary |
|---|---|---|
| Brand-first entry | Homepage, navigation, `/for-brands`, and primary calls to action lead with readiness and control | None |
| Private readiness | `/readiness` provides an immediate six-question browser-only decision map | Accounts, uploads, storage, and formal submissions remain off until data rules are contractually operational |
| No-surprise outcomes | `/what-if-we-dont-pass`, readiness, application, remediation, and program pages use one consequence model | A numerical result simulator awaits the certification rules engine |
| Evidence reuse | Existing COAs and records are requested before new testing; acceptance criteria are stated | Automated validation and an immutable Evidence Reuse Passport await a private product |
| Remediation | Public wording describes the current pre-certification support pathway and never promises certificate preservation | A separate post-certification voluntary-disclosure protocol would require governance approval |
| Cost and timing | Every potential charge and timing driver is identified; written scope precedes commitment | No fee is invented before a ratified schedule exists |
| Category readiness | One generated JSON source controls ten public category states and prevents `open` without complete release gates | All current categories truthfully remain `private_readiness_only` |
| Mark and claims | Product-specific scope, visual rules, QR pairing, review, status, suspension, removal, and reentry are documented | Visible SVGs are reference previews; production assets require qualification and control |
| Data and evidence firewall | `/what-happens-to-your-data` states current browser behavior, intended receivers, public fields, compulsory-process boundaries, and HMI exclusion | Private intake remains gated until retention and deletion terms are ratified and implemented |
| Standard stability | `/standard-stability` establishes named editions, no silent retroactivity, published transitions, and urgent-correction boundaries | Edition notices and contractual terms must instantiate the covenant |
| Public verification | Directory and verification pages truthfully show zero certified products and an inactive lookup | The register activates only with the first valid certificate |
| Brand operations | The Control Room is clearly labeled as a noindex, nonfunctional specimen | Authentication, live records, lifecycle workflows, and retailer APIs remain future products |

## Material defects corrected

1. The certification site contained a citation component that named `HeavyMetalIndex.com`, asserted Index licensing, and linked to nonexistent Index routes. It now emits certification-native citations and real certification-site links.
2. Directory, verification, and portal pages looked more operational than their data supported. They now show an honest zero-product/inactive/specimen state.
3. Public copy mixed product certification with brand-wide certification. Product scope is now explicit and linted.
4. Public pages exposed the retired clean/dirty calibration vocabulary. Those certification roles and their replacement marketing labels are removed; occurrence comparisons remain descriptive, and neither public nor machine-readable evidence assigns a percentile-based certification role.
5. Standards-register totals omitted custom rows while displaying them. The displayed count is now generated from the complete register.
6. The mark page lacked a usable control system and implied downloadable assets. It now functions as a claims and reproduction guide without releasing production art.
7. Generated table headers carried divergent inline styles across the site. Generation now canonicalizes them so the design system has one source of truth.
8. The standards register and a cost briefing overflowed on mobile. Both now fit the audit viewport.
9. Generated standards used the website build date as their effective date. They now derive the effective date from the authoritative dated edition, so a rebuild cannot masquerade as a standards revision.

## Automated regression barriers

- `tools/brand-direction-lint.mjs` rejects retired public vocabulary, brand-wide certification claims, certificate-preservation promises, misleading commercial openings, unsupported operational claims, and invalid readiness states.
- `tools/build-category-readiness.mjs` publishes category status from one data source.
- `tools/canonicalize-generated-table-heads.mjs` removes generated inline table styling before the sitewide design lint runs.
- `tools/check-all-routes.mjs` renders every route at two viewports, checks structural and typography rules, resolves local references, catches browser errors and overflow, and exercises readiness without network transmission.
- `design/v3-acceptance.cert.json` protects critical rendered states, including absence assertions for fabricated products, forms, and downloads.
- The CI workflow runs these barriers on every proposed change.

## Release judgment

The public correction is releasable because it is useful without claiming that unbuilt private infrastructure or unratified policy is live. Authentication, private uploads, a fee calculator, certification decisions, certificate issuance, production mark downloads, and retailer APIs must remain unavailable until their governance and operating controls exist. That boundary is deliberate completion of the public information architecture, not a placeholder presented as a product.
